# Валидация и анализ ошибок

## Схема

Seed — `20260928`. Выбираются 6 000 разных нормализованных текстов, по одному
полному контексту `search_*`. Длина и наличие фильтров стратифицированы
по неразмеченному benchmark.

- 4 500 запросов для обучения селектора, 1 500 для выбора вариантов.
- 6 324 разных positive items удалены из всей обучающей истории.
- Вся история удалена для 2 819 обучающих и 940 проверочных текстов.
- В fit остаются 476 457 взаимодействий.
- Корпус: benchmark плюс positives, всего 195 084 объявления.

Признаки отложенных items доступны, как у новых объявлений. Assert-проверки
исключают held-out items и cold texts из fit. Тексты ranker_train/validation
не пересекаются; одно объявление может выбираться разными holdout запросами,
поэтому эти две части не названы взаимно item-disjoint.
Метрика усредняет доли уникальных релевантных IDs по запросам.

## Ограничения

Корпус может хуже отражать конкуренцию для обучающих запросов: к benchmark
добавлены только positives, а не весь train corpus. Группы с >15 positives
в holdout не выбирались. Выбор моделей и веса смеси по одной validation
делает результат выбранного варианта разведочной оценкой.

Ансамбль получил **0.913667 локально** и **0.866246 public**. Public score
сообщил автор после отправки CSV. Без benchmark labels нельзя установить
точную причину разницы или разбирать ошибки именно public запросов.

## Ошибки и действия

| Наблюдение | Что сделано |
| --- | --- |
| BM25 без географии 0.370944 | Добавлены вероятности локаций и distance; BM25 с географией 0.798389 |
| Регион без центра получает 20 000 km | Исправлен fallback на частый выбранный город; validation пул оставлен фиксированным для отдельного опыта |
| Похожие слова ведут в другую услугу | Добавлен MNB intent transfer, сравнивались четыре настройки |
| Positives около границы top-50 | Rank/gap признаки, LightGBM LambdaRank и смеси с CatBoost |
| Глубокий CatBoost хуже | Проверены глубины 6/8/9, сохранена лучшая depth 6 |
| Дистанционные услуги, межгород и синонимы | Выделены в анализе; remote и Tiny исследовались, но не включены без законченной оценки |
| Все held-out positives без истории | Click/popularity обнулены; резервирование ответов по истории не применяется |
| Windows MemoryError при свободной RAM | Batch чтение, ранняя обрезка описаний, disk-backed матрицы, последовательные стадии |
| uint64 ключи округляются через float64 | Случайный выбор позиции вместо преобразования ключей в float |

В финальном ансамбле пропущено 139 релевантных объявлений: 64 отсутствуют
в пуле, 33 находятся близко за top-50. У 40 промахов отличается локация,
у 33 — микро-категория. Теги пересекаются и не доказывают причину.
[Полный отчёт](../reports/error_analysis.md) пересчитывается без обучения:

```bash
python src/analyze_errors.py --scores artifacts/lgbm_cb_ensemble_scores.npy \
  --model-name query_zscore_lgbm_0.90 --max-examples 12
```

## Проверка CSV

Валидатор читает IDs как строки: проверяет UTF-8, ровно `query_id,answer`,
точное множество 2 452 query IDs и регистр, отсутствие повторов, максимум
50 items с одним пробелом, формат `[0-9a-f]{16}` и принадлежность корпусу.
Exporter проверяет схемы признаков, порядок строк, SHA моделей/кэша/CSV.
Главная интеграционная проверка — генерация в чистой копии репозитория
с совпадением SHA, без чтения готового `answer.csv`.
